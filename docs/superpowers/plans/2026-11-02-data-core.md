# Data Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the app its data: every entity type, the weekly template that generates days, on-device storage with history, week rollover, goal counts, and backup/restore. The owner's starter data is a local seed file in the backup format.

**Architecture:**
- The whole `AppState` lives in memory. Pure functions take a state and return a new one.
- A store diffs old and new state by reference and writes only changed records to one SQLite table, in one transaction per change.
- Each record has a `kind`, an `id`, an indexed `date` and a JSON payload, so date-range history queries are a single indexed `SELECT`.
- Backup is the same state as one versioned JSON file.

**Tech Stack:** TypeScript, expo-sqlite (app), `node:sqlite` (tests only), Jest via jest-expo.

**Spec:** `docs/superpowers/specs/2026-11-02-life-centralized-design.md` (§3, §6). Spike results: `docs/superpowers/spike-results.md`.

## Global Constraints

- Public repo: no personal data (names, routine contents, task text, calendar data, health or finance details) in code, tests, fixtures or commits. Test fixtures use neutral words ("Item A", "Task 1").
- `seed.local.json` is gitignored and holds the owner's real data in the backup format.
- Weeks run Monday to Sunday. Blocks are, in order, `morning`, `afternoon`, `evening`, `winddown`.
- Goals: `gym`, `trading`, `cardio`. Tags: `trading`, `health`, `projects`, `life`. Urgency: `now`, `soon`, `someday`.
- Template edits apply from that point on. Past days keep what they had.
- Nothing is deleted when a day or week passes (spec §6 History).
- Seed defaults: Morning until 12:00, Afternoon 12:00–6:00, Evening 6:00–9:00, Wind down from 9:00.
- Run checks with `bash -c 'node node_modules/typescript/bin/tsc --noEmit && node node_modules/eslint/bin/eslint.js . && node node_modules/jest/bin/jest.js'`. Use the PowerShell tool for `npx`.

## Review Focus

1. **The app isn't opened for days or weeks.** Each missed week is closed exactly once, with days marked "not checked in" and goal counts saved. Closing goes back at most 8 weeks, and relaunching doesn't close again. The tests are in Task 4.
2. **Date math at DST changes, month and year ends, and Sunday.** ISO date helpers must stay on local calendar dates. The tests are in Task 1.
3. **Restoring something that isn't a current backup:** the spike export, a backup from a newer app, or an older backup missing newer collections. The first two get a plain error and change nothing. Older backups get the missing parts filled with defaults. The tests are in Task 5.
4. **The template is edited mid-week.** Today and past days keep their snapshot, and future days follow the new template. The tests are in Task 4.
5. **Several quick changes, or a failing write.** Writes apply in order and each change is one transaction. A failure is reported and doesn't corrupt what's stored. The tests are in Task 3.

```ts
export type Urgency = 'now' | 'soon' | 'someday';

export type Background = 'linen' | 'beige' | 'oat' | 'charcoal';
export type CardColor = 'sage' | 'cocoa';
export interface BlockTimes { id: BlockId; start: Minutes; end: Minutes | null } // null end = until midnight
export interface Slot { weekday: number; block: BlockId }
export interface TemplateItem { id: string; block: BlockId; title: string; time?: Minutes; minimum?: string; goal?: GoalId; backup?: Slot; note?: string }
export type When = { kind: 'block'; block: BlockId } | { kind: 'at'; time: Minutes } | { kind: 'range'; start: Minutes; end: Minutes };
export interface TemplatePlan { id: string; title: string; when: When; kind: PlanKind }
export interface TemplateDay { label?: string; note?: string; blocks: BlockTimes[]; items: TemplateItem[]; plans: TemplatePlan[] }
export interface Template { days: TemplateDay[] } // 7 entries, index 0 = Monday
export interface DayItem extends Omit<TemplateItem, 'backup'> { backup?: { date: ISODate; block: BlockId } }
export type BlockAnswer = 'done' | 'partly' | 'skipped';
export type ItemOutcome = 'done' | 'missed' | 'moved' | 'skipped';
export interface Checkin { at: string; answers: Partial<Record<BlockId, BlockAnswer>>; outcomes: Record<string, ItemOutcome>; unplannedTasks: string[] }
export interface EventSnapshot { key: string; title: string; start: string; end: string; allDay: boolean; calendarTitle: string }
export interface DayRecord { date: ISODate; label?: string; note?: string; blocks: BlockTimes[]; items: DayItem[]; plans: TemplatePlan[];

export interface Move { id: string; fromDate: ISODate; itemId: string; toDate: ISODate; toBlock: BlockId; at: string }
export interface Task { id: string; title: string; urgency: Urgency; tag: Tag; inProgress: boolean; due?: ISODate; start?: ISODate;
  planned?: { date: ISODate; block?: BlockId }; note: string; noteUpdatedAt?: string; createdAt: string; doneAt?: string }
export interface Plan { id: string; title: string; date: ISODate; when: When; kind: PlanKind; note: string; noteUpdatedAt?: string;
  addToCalendar: boolean; calendarEventId?: string; createdAt: string; fromNoteId?: string }
export interface Note { id: string; text: string; createdAt: string; turnedInto?: { kind: 'task' | 'plan'; id: string } }
export interface EventNote { key: string; title: string; date: ISODate; text: string; updatedAt: string }
export interface ImportedCalendar { id: string; title: string; color: string; isBirthdays: boolean }
export interface ImportedEvent { key: string; eventId: string; calendarId: string; title: string; start: string; end: string; allDay: boolean; date: ISODate }
export interface CalendarState { imported: boolean; offCalendars: string[]; hidden: string[]; calendars: ImportedCalendar[]; events: ImportedEvent[]; syncedAt?: string }
export interface Settings { background: Background; cards: CardColor; charcoalInDark: boolean; centralizedCalendarId?: string; lastWeekClosed?: ISODate }
export interface WeekRecord { weekStart: ISODate; goals: Record<GoalId, { count: number; target: number }> }
export interface AppState { settings: Settings; template: Template; goalTargets: Record<GoalId, number>;
  days: Record<ISODate, DayRecord>; weeks: Record<ISODate, WeekRecord>; moves: Record<string, Move>; tasks: Record<string, Task>;
  plans: Record<string, Plan>; notes: Record<string, Note>; eventNotes: Record<string, EventNote>; calendar: CalendarState }
```

### Task 3: Store and React binding

**Files:**
- Create: `src/data/store.ts`, `src/data/store.test.ts`, `src/data/StoreContext.tsx`

**Interfaces:**
- Consumes: `Db`, `migrate`, `toRecords`, `fromRecords`, `diffRecords`.
- Produces, `src/data/store.ts`:

```ts
export interface Store {
  getState(): AppState;
  subscribe(listener: () => void): () => void;
  update(fn: (s: AppState) => AppState): void;   // sync state + notify; queues the write
  replace(next: AppState): Promise<void>;         // restore: wipes all records, writes next, one transaction
  flush(): Promise<void>;                          // resolves when queued writes finish
}
export function createStore(db: Db, onError?: (e: unknown) => void): Promise<Store>; // migrates, loads
```

  - `update` with a function that returns the same reference does nothing: no notify, no write.
  - Writes run one after another, in a single queue. Each is one transaction holding all of that change's puts (`INSERT OR REPLACE`) and deletes.
  - A failed write calls `onError` and the queue keeps going.
- Produces, `src/data/StoreContext.tsx`:
  - `StoreProvider({ store, children })`
  - `useStore(): Store`
  - `useAppState(): AppState` uses `useSyncExternalStore` over `subscribe` and `getState`.

  - `replace(next)` leaves only `next`'s rows. A task present only before the replace is gone.

### Task 4: Days, week rollover and goal counts

**Files:**
- Create: `src/domain/lifecycle.ts`, `src/domain/lifecycle.test.ts`

**Interfaces:**
- Consumes: `generateDayRecord`, the date helpers, and the types.
- Produces:
  - `openDays(s: AppState, today: ISODate): AppState`
    - Makes sure a `DayRecord` exists for every date from `weekStartOf(today)` through `today`, generated from the current template.
    - Returns `s` itself when nothing was missing.
  - `closeWeeks(s: AppState, today: ISODate): AppState`. Let `current = weekStartOf(today)`.
    - If `settings.lastWeekClosed` is unset, it sets it to `addDays(current, -7)` and closes nothing (a fresh install doesn't backfill).
    - Otherwise it closes each week `w` from `max(lastWeekClosed + 7, current − 56 days)` through `current − 7`. Closing a week means:
      1. Generate any missing days of `w`.
      2. Set `notCheckedIn: true` on days without `checkin`.
      3. Write `weeks[w] = { weekStart: w, goals: { g: { count: goalCounts(s, w)[g], target: goalTargets[g] } } }`.
    - Then it sets `lastWeekClosed = current − 7`.
    - Returns `s` itself when there's nothing to close.
  - `goalCounts(s: AppState, weekStart: ISODate): Record<GoalId, number>`. It counts the ticked items with a goal on that week's day records. A tick keyed `move:<id>` counts the goal of the moved item, found through `moves[id]` in the from-day's items.
  - `startOfDay(s: AppState, today: ISODate): AppState` is `openDays(closeWeeks(s, today), today)`. The shell runs it on launch and on return to the foreground.

### Task 5: Backup and restore

**Interfaces:**
- Produces, `src/data/backup.ts`:
  - `BACKUP_VERSION = 1`
  - `interface BackupFile { app: 'life-centralized'; kind: 'backup'; version: number; exportedAt: string; data: AppState }`
  - `makeBackup(s: AppState, now: Date): BackupFile`
  - `parseBackup(text: string): { ok: true; state: AppState } | { ok: false; error: string }`

  - Bad JSON: `"That file isn't a backup."`

  - `pickBackup(): Promise<{ ok: true; state: AppState } | { ok: false; error: string } | null>` returns null if cancelled.
